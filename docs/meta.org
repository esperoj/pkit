#+title: pkit meta

Record database: sqlite tables for typed records, a JSON file repo for
sync between machines, and integrity checks.

* CLI

#+begin_src sh
pkit meta dump [REPO]                                # database -> <repo>/<table>.json; prints the record count
pkit meta load [--refresh] [--lang LANG] [SOURCE]    # JSON repo or source URL -> database; prints the count
pkit meta migrate                                   # apply pending migrations; prints each applied name
pkit meta validate                                   # orphan link rows, duplicate ids/identifiers; silent when clean
#+end_src

~REPO~ defaults to ~[meta] repo_path~. The database comes from
~[meta] db_path~ or ~$PKIT_META_DB_PATH~. When loading a source URL
(such as ~wikidata:Q42~ or ~wikidata:Q82050~), existing records matched by
identifier are skipped unless ~--refresh~ is passed. ~validate~ prints
each issue to stdout and exits 1 if any were found (0 when clean).
~migrate~ prints one newly applied migration name per line and is silent
when the database is current. ~dump~ and ~validate~ open the database
read-only.

* Languages

Source imports support ~auto~, ~en~, ~vi~, and ~zh~ via ~--lang~,
~$PKIT_META_LANG~, or ~[meta] lang~ in ~~/.config/pkit/config.toml~
(default ~auto~):

#+begin_src toml
[meta]
lang = "auto"
#+end_src

- *Main fields* (~title~, ~name~, ~description~, ~series~, ~publishers~, ~developers~)
  use the selected language. Under ~auto~, an item uses its original
  language (~P407~ / ~P1559~ / ~P103~ / ~P1476~) when unambiguous and in
  ~en~, ~vi~, or ~zh~; otherwise it falls back to ~en~ (and then ~zh~ → ~vi~
  → original language if a translation is missing).
- *Chinese script priority*: Simplified first (~zh-hans~ → ~zh-cn~ → ~zh~
  → ~zh-sg~ → ~zh-hant~ → ~zh-tw~ → ~zh-hk~).
- *Taxonomy fields* (~kind~, ~lang~, ~genres~, ~gender~, ~country~,
  ~occupations~, ~platforms~, ~licenses~, ~directors~, ~performers~) stay
  in English so queries remain uniform.
- *Translations in ~extra["i18n"]~*: every available entry in ~en~, ~vi~,
  ~zh~, plus the item's original language when outside those three, is
  stored under ~extra.i18n.<lang>~.
- *One mapping per type*: each import plan's QID-to-kind table (see
  ~pkit/meta/wikidata/plans.py~) drives both what it matches (~P31~
  classes and external-ID properties) and the ~kind~ it assigns.

* Record types

| Type       | Covers                                            | id              |
|------------+---------------------------------------------------+-----------------|
| ~Text~     | Books, manga, comics, articles, journals, manuals | UUID4           |
| ~Video~    | Movies, series, episodes, anime                   | UUID4           |
| ~Sound~    | Songs, albums, singles, podcasts                  | UUID4           |
| ~Person~   | Authors, creators                                 | UUID4           |
| ~Software~ | Applications, libraries, OSes, video games        | UUID4           |
| ~File~     | Content-addressed files (~pkit.archive~)          | ~sha256:<hex>~  |

* Migrations

One table per ~.sql~ file under ~pkit/meta/migrations/~, applied in name
order and recorded in a ~_migrations~ table:

#+begin_example
0001_files.sql  0002_persons.sql  0003_texts.sql  0004_text_authors.sql
0005_software.sql  0006_videos.sql  0007_sounds.sql
#+end_example

Connections check migrations read-only first and only take a write lock
when something is pending, so concurrent readers (a parallel
~pkit archive verify~ sweep) never block each other; ~migrate()~ enables
WAL journaling best-effort and is safe to run concurrently. Link tables
deliberately carry no foreign keys, so records can be imported in any
order.

* Sync between machines

#+begin_src sh
pkit meta dump ~/records       # then commit ~/records to git
git pull && pkit meta load     # on the other machine
#+end_src

One file per table, one JSON array per file, rows sorted by id, so
unchanged data produces byte-identical files (clean git diffs). Link
tables are not synced separately — links live inside their parent rows
and are rebuilt on load. Browse pending repo changes with
~scripts/meta-diff-fzf~ (see [[file:../scripts/README.org][scripts/README.org]]).

* Library

#+begin_src python
from pkit.meta import dump, load
from pkit.meta.db import MetaDB
from pkit.meta.models import File, Person, Software, Sound, Text, Video

with MetaDB() as db:
    db.put(Text(id="t1", title="Pandora Hearts", kind="manga", author_ids=["p1"]))
    db.put(Software(id="s1", title="Tales of the Abyss", kind="game", series=["Tales"]))
    record = db.get("t1")                       # by id, any table
    records = db.find(Text)                     # newest first; sort= flips the order
    oldest = db.find(Text, sort="created_at")   # id, slug, timestamps, scalar fields
    dark = db.find(Text, where={"genres": "dark fantasy", "author_ids": ["p1", "p2"]})
    author = db.find_one(where={"identifiers": "wikidata:Q42"})       # any table
    by_name = db.find_one(Person, where={"name": "Jun"})              # one table
    issues = db.validate()                      # orphans, duplicate ids/identifiers/sha256s

with MetaDB(readonly=True) as db:  # no DDL, no write lock, no migrations
    record = db.get("t1")

dump.dump("~/records")  # records -> JSON repo
load.load("~/records")  # JSON repo -> records
load.load("wikidata:Q82050")  # import a game or software item from Wikidata
load.load("wikidata:Q42", refresh=True, lang="zh")  # force Chinese main fields
#+end_src

Four query methods cover everything:

- ~get(record_id)~ — fetch by id across the stored tables.
- ~find(model, where=..., sort=..., limit=..., offset=...)~ — list one
  table. ~where~ ANDs filters: scalar fields compare by equality (a
  collection becomes ~IN~), array fields (~identifiers~, ~genres~, ...)
  match by membership, link fields (~author_ids~) match through the link
  table; an empty collection matches nothing.
- ~find_one(model=None, where=...)~ — the deduplication probe: first
  match on one model, or on every stored model carrying the ~where~ keys.
  ~find_one(where={"identifiers": "wikidata:Q42"})~ answers "is this item
  already imported, whatever its type".
- ~exists(x)~ is ~find_one(...) is not None~; unknown types, sorts and
  fields raise ~ValueError~ listing known values.

~put~ accepts a record or a plain mapping and returns the stored record;
missing ids and slugs are filled in. Domain records use UUID4 ids and
keep external IDs (~wikidata:...~, ~isbn13:...~, ~igdb:...~, ...) in
~identifiers~. ~File.id~ is ~sha256:<hex>~ so re-adding the same bytes is
the same row across machines; ~sha256~/~sha1~/~md5~ live in dedicated
indexed columns on ~files~, and ~File.name~ is the tree name ~pkit
archive add~ first recorded for the bytes (first add wins).
