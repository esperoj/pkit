#+title: pkit meta

Record database: sqlite tables for typed records, a JSON file repo for
sync between machines, and integrity checks.

* CLI

#+begin_src sh
pkit meta dump [REPO]                                # database -> <repo>/<table>.json; prints the record count
pkit meta load [--refresh] [--lang LANG] [SOURCE]    # JSON repo or source URL -> database; prints the count
pkit meta migrate                                   # apply pending migrations; prints each applied name
pkit meta validate                                   # orphan link rows, duplicate ids/identifiers; silent when clean
#+end_src

~REPO~ defaults to ~[meta] repo_path~. The database comes from
~[meta] db_path~ or ~$PKIT_META_DB_PATH~. When loading a source URL
(such as ~wikidata:Q42~ or ~wikidata:Q82050~), existing records matched by
identifier are skipped unless ~--refresh~ is passed. ~validate~ prints
each issue to stdout and exits 1 if any were found (0 when clean).
~migrate~ prints one newly applied migration name per line and is silent
when the database is current. ~dump~ and ~validate~ open the database
read-only.

* Languages

Source imports support ~auto~, ~en~, ~vi~, and ~zh~ via ~--lang~,
~$PKIT_META_LANG~, or ~[meta] lang~ in ~~/.config/pkit/config.toml~
(default ~auto~):

#+begin_src toml
[meta]
lang = "auto"
#+end_src

- *Main fields* (~title~, ~name~, ~description~, ~series~, ~publishers~, ~developers~)
  use the selected language. Under ~auto~, an item uses its original
  language (~P407~ / ~P1559~ / ~P103~ / ~P1476~) when unambiguous and in
  ~en~, ~vi~, or ~zh~; otherwise it falls back to ~en~ (and then ~zh~ → ~vi~
  → original language if a translation is missing).
- *Chinese script priority*: Simplified first (~zh-hans~ → ~zh-cn~ → ~zh~
  → ~zh-sg~ → ~zh-hant~ → ~zh-tw~ → ~zh-hk~).
- *Taxonomy fields* (~kind~, ~lang~, ~genres~, ~gender~, ~country~,
  ~occupations~, ~platforms~, ~licenses~, ~directors~, ~performers~) stay
  in English so queries remain uniform.
- *Translations in ~extra["i18n"]~*: every available entry in ~en~, ~vi~,
  ~zh~, plus the item's original language when outside those three (at most
  four entries), is stored under ~extra.i18n.<lang>~.
- *One mapping per type*: each import plan's QID-to-kind table (see
  ~pkit/meta/wikidata/plans.py~) drives both what it matches (~P31~
  classes and external-ID properties) and the ~kind~ it assigns, so
  adding a type stays one table plus one ~Plan~.

* Record types

| Type       | Covers                                            | id              |
|------------+---------------------------------------------------+-----------------|
| ~Text~     | Books, manga, comics, articles, journals, manuals | UUID4           |
| ~Video~    | Movies, series, episodes, anime                   | UUID4           |
| ~Sound~    | Songs, albums, singles, podcasts                  | UUID4           |
| ~Person~   | Authors, creators                                 | UUID4           |
| ~Software~ | Applications, libraries, OSes, video games        | UUID4           |
| ~File~     | Content-addressed files (~pkit.archive~)          | ~sha256:<hex>~  |

* Sync between machines

#+begin_src sh
pkit meta dump ~/records       # then commit ~/records to git
git pull && pkit meta load     # on the other machine
#+end_src

One file per table, one JSON array per file, rows sorted by id (SQLite-side:
~db.find(cls, sort="id")~), so unchanged data produces byte-identical files
(clean git diffs). Link tables are not synced separately — links live inside
their parent rows and are rebuilt on load. Browse pending repo changes with
~scripts/meta-diff-fzf~ (see [[file:../scripts/README.org][scripts/README.org]]).

* Library

#+begin_src python
from pkit.meta import dump, load
from pkit.meta.db import MetaDB
from pkit.meta.models import File, Person, Software, Sound, Text, Video

with MetaDB() as db:
    db.put(Text(id="t1", title="Pandora Hearts", kind="manga", author_ids=["p1"]))
    db.put(Software(id="s1", title="Tales of the Abyss", kind="game", series=["Tales"]))
    db.put(Video(id="v1", title="Ghost in the Shell", kind="movie", duration=4800))
    record = db.get("t1")
    records = db.find(Text)  # newest first (find(cls, sort="-updated_at") by default)
    oldest = db.find(Text, sort="created_at")  # any sortable column: id, slug, created_at, updated_at, or a scalar field; "-" flips the order
    matches = db.find(where={"identifiers": "wikidata:Q42"})
    dark = db.find(Text, where={"genres": "dark fantasy", "author_ids": ["p1", "p2"]})
    author = db.get("wikidata:Q42", by="identifiers")  # probe any queryable field
    known = db.exists("p1")  # str probes id by default; by= picks another field
    issues = db.validate()  # orphans, duplicate ids/identifiers/sha256s

with MetaDB(readonly=True) as db:  # no DDL, no write lock, no migrations
    record = db.get("t1")

with MetaDB("records.db", auto_migrate=False) as db:
    applied = db.migrate()  # same as `pkit meta migrate`; [] when current

dump.dump("~/records")  # records -> JSON repo
load.load("~/records")  # JSON repo -> records
load.load("wikidata:Q82050")  # import a game or software item from Wikidata
load.load("wikidata:Q42", refresh=True, lang="zh")  # force Chinese main fields
#+end_src

~put~ accepts a record or a plain mapping; ~get~/~find~ return typed
records. Domain records (~Text~, ~Video~, ~Sound~, ~Person~, ~Software~,
including source imports) use UUID4 as ~id~ and store all external IDs
(~wikidata:...~, ~isbn13:...~, ~igdb:...~, ~flathub:...~, ~viaf:...~) in
~identifiers~.
On ~Text~, ~Video~, and ~Software~, ~kind~ distinguishes formats (~manga~,
~novel~, ~article~, ~game~, ~software~, ~movie~, ~series~, ~episode~,
~song~, ~album~, ~podcast~, …), ~series~ is a list of strings, and
publishers, developers, directors, and performers are plain strings
(~Text.author_ids~ links to ~Person~). ~Video~ and ~Sound~ carry ~duration~
in seconds. Personal reviews and activity logs live outside pkit, in the
org-mode knowledge base.
~File.id~ is ~sha256:<hex>~ so
re-adding the same bytes is the same row across machines; ~sha256~,
~sha1~ and ~md5~ live in dedicated indexed columns on ~files~ (fast
~by="sha1"~ / ~by=("sha1", "md5")~ lookups), and ~File.identifiers~ is
for external IDs only. ~File.name~ is the tree name ~pkit archive add~
first recorded for the bytes (first add wins); a plain scalar column, so
~find(where={"name": ...})~ works. ~db_path~ defaults to ~[meta] db_path~ /
~$PKIT_META_DB_PATH~.

** Queries and probes

~find~'s ~where~ mapping ANDs filters: scalar fields (~id~, ~slug~, ~name~,
…) compare by equality (a collection becomes ~IN~), array fields
(~identifiers~, ~genres~, ~locations~, …) match by membership, and link
fields (~author_ids~) match through the link table; an empty collection
matches nothing, and unknown or dict fields (~extra~) raise ~ValueError~.
With no ~record_type~, only stored models carrying every ~where~ key are
searched.

~get~ / ~exists~ probe a record id (by ~id~ unless ~by~ says otherwise), a
~Record~ instance, or a mapping — with ~"type"~ to pin the model, or without
to probe whichever stored model has each key. Each non-empty ~unique~ field
of the target model is tried in order as its own indexed ~LIMIT 1~ query
(the first hit wins; ~File~ probes ~id~, ~sha256~, ~sha1~, ~md5~), and empty
values (~None~, ~""~, ~[]~) are skipped. Probing a mapping with
~"id": ""~ instead of a random UUID is the safe way to match on the other
fields only. ~put~ stays keyed on ~id~ (~ON CONFLICT(id)~).

Connections check migrations read-only first and only take a write lock
when something is pending, so concurrent readers (a parallel
~pkit archive verify~ sweep) never block each other; ~migrate()~ enables
WAL journaling best-effort and is safe to run concurrently.
