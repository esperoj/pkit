#+title: pkit archive

Personal archive manager, inspired by git-annex. A library and a thin CLI.

* Model

| Layer                 | Holds                                   |
|-----------------------+-----------------------------------------|
| git                   | names, folders, history (symlinks are committed) |
| ~.git/pkit-archive/~  | local content, named by sha256, mode ~0444~ |
| meta ~files~ table    | content identity + *remote* locations   |

Tree entries are *relative symlinks* into the CAS. The target basename is the
hash, so renames, moves and a changed CAS root never lose identity. Local paths
are never stored in the database; the record keeps only ~name~, the tree name
~add~ first saw the content under.

Objects are read-only from creation. Permissions stop mutation; the location
log stops deletion.

* Example

#+begin_src python
from pkit import archive

manga = "/mnt/archive/pandora-hearts"

archive.add(manga)  # move into CAS, leave symlinks
archive.copy(manga, "ia:pandora-hearts")  # check dest, upload missing, register
archive.match("ia:pandora-hearts")  # register existing copies, no transfer
archive.verify(manga)  # report local + remote integrity
archive.drop(manga)  # delete local copy after proving a remote
archive.get(manga)  # fetch it back, verified
#+end_src

* CLI

#+begin_src text
pkit archive add PATH...               # ingest: CAS, symlinks, records
pkit archive fix PATH                  # re-point links, re-assert perms
pkit archive copy PATH REMOTE           # transfer missing, register
pkit archive match REMOTE               # register known content, no transfer
pkit archive verify PATH [REMOTE...]    # report local + remote integrity
pkit archive verify-wayback [--days N]  # re-verify stale wayback captures
pkit archive drop PATH                  # delete local copy once a remote is proven
pkit archive get PATH [REMOTE] [--quiet] # restore a verified copy, with progress
pkit archive forget PATH                # delete records for dangling links
pkit archive remove-location PATH LOCATION
pkit archive cleanup [--age 35d] [--dry-run] # delete old staged files
#+end_src

Every command takes ~--json~ for structured output. Plain output is one
summary line (plus data lines: checks for ~verify~, missing paths for
~fix~, registered locations for ~copy~). ~verify~ prints
~location<TAB>status~ per check and exits 1 when any check is not ~ok~ —
that is the alert a sweep looks for. The database comes from ~[meta]~
config; the CAS root is found by walking up to ~.git~ (override with
~cas_dir=~ in the library, or place a ~.git~ directory above the tree).

* Functions

| Function                          | Purpose                                                                 |
|-----------------------------------+-------------------------------------------------------------------------|
| ~add(path)~                       | hash, move into CAS, symlink, register (records ~name~). Never follows foreign symlinks. |
| ~fix(path)~                       | re-point links at the current CAS, re-assert ~0444~. No DB, no network. |
| ~copy(path, remote)~              | list dest once, transfer only missing, register. Meaningful names.      |
| ~match(remote)~                   | list dest once, register hashes already known. No transfer.             |
| ~verify(path, remotes=())~        | report ~ok~ / ~mismatch~ / ~missing~ / ~unknown~ per record. Never prunes. |
| ~verify_wayback(days=32)~         | re-verify wayback captures older than ~days~, from the database.        |
| ~drop(path)~                      | verify one remote live, then delete the object. Link stays dangling.    |
| ~get(path, remote=None, progress=None)~ | restore an object; the download is verified before it enters the CAS. |
| ~forget(path)~                    | delete records for dangling links. Refuses while the object exists.     |
| ~remove_location(path, location)~ | manual cleanup after a verify report.                                   |
| ~cleanup(age="35d", dry_run=False)~ | delete staged files older than the safety window.                      |

Every path argument accepts a tree (one result per CAS link under it), a
single file (even dangling), a CAS path, or a ~sha256:<hex>~ id.
~verify~, ~drop~, ~get~ and ~remove_location~ return a tuple of per-record
results. ~verify~ treats ~"local"~ as a pseudo-location, so remote-only
checks need no local content.

All functions accept ~db_path=~ and ~cas_dir=~ overrides; remote ones also accept
~config_path=~.

* Backends

| Scheme           | Mechanism                                              |
|------------------+--------------------------------------------------------|
| ~name:path~      | rclone (~ia:~, ~s3:~, ~gdrive:~, …). Listing, copy, hash check. |
| ~wayback:prefix~ | CDX listing, staging upload, SPN2 capture.             |

~wayback:~ is reserved; do not name an rclone remote that.

Wayback locations are full capture URLs with a timestamp, because one URL can
hold different content over time:

#+begin_src text
wayback:https://web.archive.org/web/20260101120000id_/https://files.example.com/manga/v1.cbz
#+end_src

CDX digests are base32 SHA1, converted to hex and matched against the ~sha1:~
identifier. Only ~200~ captures are used, and only the oldest capture per
(content, URL) is kept, so re-matching is idempotent.

* Downloads and progress

~get~ downloads through ~pkit.lib.http~'s ~downloader~ choice: ~auto~
(default) uses ~aria2c~ when it is installed — resume, connections, its own
retries — and falls back to the stdlib HTTP client otherwise. Pin the
engine with the ~[http]~ section (~downloader = "http"~) or
~$PKIT_HTTP_DOWNLOADER~; ~downloader="http"|"aria2c"|"auto"~ on the
~HttpClient.download~ call wins over both.

Unless ~--quiet~ is passed, ~pkit archive get~ shows a progress line on
stderr (~12.3MiB/20MiB 61% 2.5MiB/s ETA:3s~) whenever stderr is a
terminal — pipes and logs stay clean. Progress is diagnostics only; the
download is always re-verified by hash before it enters the CAS.

* Config

#+begin_src toml
[archive]
wayback_url = "https://files.example.com"

[wayback]
host = "archive.esperoj.eu.org"   # mirror rewriting web.archive.org requests

[http]
proxy_prefix = ""                 # or route all rewritten hosts through a proxy
downloader = "auto"               # auto | aria2c | http (auto prefers aria2c)

[http.hosts]
"web.archive.org" = "archive.esperoj.eu.org"
#+end_src

~PKIT_ARCHIVE_WAYBACK_URL~, ~PKIT_WAYBACK_HOST~, ~PKIT_HTTP_PROXY_PREFIX~ and
~PKIT_HTTP_DOWNLOADER~ override them. Stored ~wayback:~ locations are always
canonical ~https://web.archive.org/...~ URLs; the mirror host or proxy only
rewrites requests at the transport layer (see [[file:wayback.org][docs/wayback.org]]).

Staging uses the rclone remote ~pkit-archive:~ (invoked through
~pkit.lib.rclone~). Staging is *temporary and never registered as a location* —
only the Wayback capture is.

Wayback captures are registered unverified because CDX indexing lags. The
monthly rhythm:

1. *Sweep the tree* — ~verify~ over the CAS links; a sharded, resumable
   daily sweep works well:

#+begin_src sh
scripts/batch-verify --shard "$(date +%-d)" --delay 5 logs/verify-$(date +%Y-%m).tsv
#+end_src

2. *Re-verify the index* — captures older than ~32 days~ get a second look,
   straight from the database (no tree walk):

#+begin_src sh
pkit archive verify-wayback            # --days 32; exits 1 when any check is not ok
#+end_src

3. *Reclaim the stage* — once re-verification has had its window, delete the
   staged copies older than ~35 days~ (rclone does the age filtering;
   ~--dry-run~ reports first):

#+begin_src sh
pkit archive cleanup --dry-run         # e.g. "7 staged files older than 35d ..."
pkit archive cleanup                   # --age 35d
#+end_src

#+begin_src sh
scripts/archive-pack -r age1... -s 100M big-dir/                 # deterministic, encrypted, chunked
#+end_src

See [[file:../scripts/README.org][scripts/README.org]]. ~drop~ always verifies one location live, so an
unverified registration can never authorize a deletion. ~verify~ and
~verify-wayback~ open the database read-only, so parallel sweeps never
contend for the SQLite write lock.

* Git workflow

#+begin_src sh
git mv old new && python -c "from pkit import archive; archive.fix('.')"
#+end_src

~git mv~ renames a link without rewriting its target, so run ~fix~ afterwards.
Keep the repository and CAS on a filesystem that supports symlinks (Termux home
does; ~/sdcard~ does not).

* Errors

~InputError~ (bad input, missing prerequisite), ~TransientError~ (retry later),
~ArchiveError~ (everything else). Results are frozen dataclasses.

* Sync between machines

#+begin_src python
from pkit.meta import dump, load

dump.dump("~/records")  # records -> JSON repo (commit it)
load.load("~/records")  # JSON repo -> records on the other machine
#+end_src

Or from the shell: ~pkit meta dump~ / ~pkit meta load~
(see [[file:meta.org][docs/meta.org]]).

The CAS is per-machine; the record repo is shared. Wayback locations can be
rebuilt from CDX alone if the database is lost.
