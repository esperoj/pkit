#+title: pkit workflow scripts

Project-level helpers, kept out of the ~pkit~ Python package on purpose:
they glue ~git~, ~parallel~ and ~pkit~ commands together in the shell and
are not part of any SDK contract. Make them executable once after cloning:

#+begin_src sh
chmod +x scripts/*
#+end_src

* Scripts

| Script            | Purpose                                                       |
|-------------------+---------------------------------------------------------------|
| ~batch-run~       | Run one command per stdin item through GNU parallel, resumable |
| ~batch-verify~    | Resumable, sharded ~pkit archive verify~ over a tree           |
| ~meta-diff-fzf~   | Browse record repo changes (working tree vs HEAD) in ~fzf~     |
| ~archive-pack~    | Deterministic ~tar.zst~ packing, optional ~age~ + ~split~      |

** batch-run — the batch engine

#+begin_src sh
producer | batch-run [OPTIONS] -- COMMAND...
#+end_src

Runs COMMAND once per stdin item through GNU ~parallel~, recording every
job in a persistent joblog. Items are NUL-separated when the stream
carries NUL bytes (~find -print0~) or one per line. The command may use
parallel's replacement strings: ~{}~ (item), ~{/}~ (basename), ~{//~~
(dirname), ~{.}~, ~{/.}~.

Options: ~--log FILE~ (default: ~logs/batch-<hash>.tsv~, derived from the
command words — same command, same log), ~--jobs N~ (default 4),
~--delay SECS~, ~--fresh~ (discard the joblog, start over), ~-h~.

#+begin_src sh
find manga/ -name '*.cbz' -print0 |
  batch-run --log logs/fix-2026-10.tsv -- 'pkit archive fix {//}'
#+end_src

Output is tagged per job and printed live; a summary goes to stderr.
Exit status: 0 when every job of this run succeeded, 1 when any failed,
2 for usage errors.

Without ~--log~, batch-run derives one: ~logs/batch-<16 hex>.tsv~, the hash
of the command words. Same command, same log — a rerun resumes where the
last one stopped and retries its failures; a different command gets its
own log and never collides. Copy/upload batches work directly on top:

#+begin_src sh
# a month of captures to an rclone remote (ia:, s3:, gdrive: ...)
find 2026-10/ -type f -print0 |
  batch-run -- 'rclone copyto {} ia:me/2026-10/{/}'

# each file into the Wayback Machine (pkit stages and captures per file)
find books/ -type l -print0 |
  batch-run --delay 5 -- 'pkit archive copy {} wayback:'
#+end_src

Pass ~--log~ explicitly when a batch needs a time-scoped name
(~logs/copy-2026-10.tsv~), when two commands share one item set, or when
running the same command from several directories (each derives its own
~./logs~). Run one batch at a time per command: the default log is a
resume record, not a lock.

** batch-verify — verify CAS-linked content

#+begin_src sh
batch-verify [OPTIONS] LOG [TREE...]
#+end_src

Collects the unique ~sha256~ ids behind a tree's CAS symlinks and runs
~pkit archive verify~ on one representative link per id — each content
hash is verified exactly once, no matter how many links point at it.
~--shard N[/M]~ verifies only every M-th id (bare N means N/31, a daily
sweep); ~-- CMD~ overrides the verification command.

#+begin_src sh
# verify everything under the repo, resumable
batch-verify logs/verify-2026-10.tsv ~/manga

# one daily shard of a monthly cycle, gentle with the Wayback rate limit
batch-verify --shard "$(date +%-d)" --delay 5 logs/verify-$(date +%Y-%m).tsv .
#+end_src

A tree with no CAS links is an error: a sweep wants to hear about that.

** Job-log lifecycle

One joblog per batch — at an explicit path, or the command-derived default —
that is the whole system:

- *Resume*: re-running the same command with the same ~--log~ skips items
  that succeeded and retries the failed ones (parallel's
  ~--resume-failed~). An interrupted batch (Ctrl-C, crash, reboot)
  resumes the same way: completed jobs are already in the log and are
  skipped.
- *Retry*: nothing extra to do — failures are simply re-run on the next
  invocation. The summary names every failed job.
- *Archive or clean up*: only after a run reports ~0 failed~:

#+begin_src sh
mkdir -p logs/done
mv logs/copy-2026-10.tsv logs/done/     # the batch is finished; start November fresh
#+end_src

Deleting a log with unfinished work re-runs those items — never destroys
data, only time.

- *Watch progress*: job output streams by live; ~tail -f LOG~ shows the
  raw joblog (tab-separated: seq, host, start, runtime, exitval, ...).

The log keys on the items, not the command: the default log name is the
hash of the command words, so the mapping happens by itself; a log keyed
differently (an explicit ~--log~ shared by several commands) wants a
~--fresh~ when the command changes.

** meta-diff-fzf

#+begin_src sh
scripts/meta-diff-fzf [REPO]        # REPO defaults to $PKIT_META_REPO or 'records'
#+end_src

Compares every ~<repo>/<table>.json~ against ~HEAD~ (records are keyed by
~id~ inside each JSON array), lists added/modified/deleted records as
~table<TAB>id<TAB>status<TAB>title-or-name~, and opens ~fzf~ with a
per-record before/after diff as the preview. The selected line is printed
to stdout. ~REPO~ may be any directory of a git work tree; JSON handling
uses the Python standard library, so ~jq~ is not required.

Exits 2 when ~git~, ~python3~ or ~fzf~ is missing (or ~REPO~ is not a git
work tree), and 1 when there are no record changes.

** archive-pack

#+begin_src sh
scripts/archive-pack [-o FILE] [-r PUB ...] [-R] [-s SIZE] PATH
#+end_src

Packs ~PATH~ into a reproducible ~tar.zst~ — ~--sort=name~,
~--mtime='UTC 1970-01-01'~, ~--owner=0 --group=0 --numeric-owner~ — so the
same bytes always produce the same archive (clean CAS identity). With
~-r PUB~ (repeatable) or ~-R~ (passphrase) the archive is encrypted with
~age~ into ~<name>.tar.zst.age~; with ~-s SIZE~ (e.g. ~100M~) the result is
split into ~FILE.part-aa~, ~FILE.part-ab~, ... chunks. Chunks and whole
archives are ordinary files, ready for ~pkit archive add~.

* External tools

| Tool            | Used by                     | Required                |
|-----------------+-----------------------------+-------------------------|
| ~parallel~      | ~batch-run/verify~          | always (with perl)      |
| ~find~, ~sort~  | ~batch-verify~              | always (GNU)           |
| ~git~           | ~meta-diff-fzf~             | always                  |
| ~python3~       | ~meta-diff-fzf~             | always (stdlib only)    |
| ~fzf~           | ~meta-diff-fzf~             | always                  |
| ~tar~, ~zstd~   | ~archive-pack~              | always                  |
| ~age~           | ~archive-pack~              | only with ~-r~ / ~-R~   |
| ~split~         | ~archive-pack~              | only with ~-s~          |
| ~pkit~          | ~batch-verify~              | on ~PATH~ (~make install~) |

GNU ~tar~ / ~find~ / ~coreutils~ / ~parallel~ are assumed (Termux and
Linux ship them; on macOS install ~coreutils~ / ~gnu-tar~ / ~parallel~).
