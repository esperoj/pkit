#+title: pkit — Engineering Guide

BusyBox-style personal CLI toolkit: one ~pkit~ command, three tools
(~archive~, ~meta~, ~wayback~), zero runtime dependencies.

Values: durability, simplicity, borrowed standards over novelty.

* 1. Philosophy

*Borrow standards, never invent.* Unix CLI conventions, Python SDK conventions
(exceptions for failure, return values for success), pytest, PEP 8/257,
stdlib first. No custom error taxonomies, no bespoke JSON error metadata.

*80/20 pragmatism.* Solve the real problem cleanly. No plugin systems, no DI,
no logging frameworks, no metrics, no excessive option flags.

*Minimal simplicity.* Best code is code that doesn't exist. Functions over
classes when stateless. Dataclasses over custom objects. Small modules, one
responsibility. Every abstraction earns its place.

*Unix philosophy.* stdout = data. stderr = diagnostics. exit codes = scripts.
stdin = piping. Success → print result to stdout, exit 0. Failure → short
diagnostic to stderr, exit non-zero.

*Longevity.* Stable Python features, mature libraries, obvious boundaries,
easy deletion. Avoid: trendy deps, over-clever typing, internal DSLs.

* 2. Architecture

#+begin_src text
pkit/
├── cli.py               # BusyBox dispatcher (no argparse needed)
├── version.py           # version from installed distribution metadata
├── lib/                 # shared kernel, tool-agnostic (the ONLY shared home)
│   ├── aria2c.py        # aria2c wrapper: resumable downloads, progress
│   ├── cli.py           # exit codes, emit, fail, progress, run_tool
│   ├── config.py        # TOML file + environment, one precedence rule
│   ├── http.py          # HttpClient: transport, timeout, HttpError, URL rewriting, downloader
│   ├── rclone.py        # rclone wrapper: run, exit-code mapping, lsjson, delete
│   ├── shell.py         # run external commands
│   ├── sql.py           # SQL builders: quoting, placeholders, filters, sorts, upserts
│   └── sqlite.py        # connect, migrations, the Database base class
├── meta/
│   ├── cli.py           # dump / load / migrate / validate
│   ├── config.py, db.py, models.py, serialize.py
│   ├── dump.py, load.py, source.py
│   ├── wikidata/        # extract.py (entity->values), plans.py, client.py
│   └── migrations/      # one table per .sql file
├── archive/
│   ├── cli.py           # add/fix/copy/match/verify/verify-wayback/drop/get/forget/cleanup/...
│   └── cas.py, db.py, errors.py, remote.py, rclone.py, wayback.py
└── wayback/
    ├── cli.py           # save, cdx query/list/export (thin, argparse)
    └── client.py        # Wayback SDK client

scripts/                 # project workflow helpers, outside the package
└── meta-diff-fzf, archive-pack, batch-run, batch-verify
#+end_src

Every tool has three entry points (console script ~pkit-<tool>~, BusyBox
subcommand ~pkit <tool>~, module ~python -m pkit.<tool>~) — one ~main()~ in
each ~cli.py~, so all three stay in lockstep by construction.

** Layering (the modular rule)

One package, four independently liftable parts — checked by
~tests/unit/test_boundaries.py~ so the rule is a contract, not a diagram:

#+begin_src text
lib       (kernel; imports stdlib + pkit.version only)
wayback   (standalone SDK; imports lib)
meta      (records data layer; imports lib)
archive   (CAS + location log; imports lib, wayback and meta)
#+end_src

Nothing imports upward, and the tools' SDKs stay peers: the only cross-tool
edges are archive's declared downward ones — meta (the location log lives
in the records database) and wayback (captures and CDX listings go through
its client). Each part could be lifted out as its own small project with
~pkit.lib~ beneath it; until that day arrives, one install keeps the
personal scale honest.

** Boundaries

| Rule                          |                                                                        |
|-------------------------------+------------------------------------------------------------------------|
| SDK modules (~client.py~, ~db.py~) | Must NOT print, or know stdout/stderr/exit codes                 |
| ~lib/*~                       | Tool-agnostic only; general wrappers (~aria2c~, ~rclone~) live beside it; scripts may import ~pkit.lib~ directly |
| External-tool wrappers        | ~lib/aria2c.py~ and ~lib/rclone.py~ wrap the CLI; ~archive/rclone.py~ only adapts rows/Hashes onto them |
| Wikidata                       | Stays in ~pkit.meta~: it maps onto record models, so it is not a lib wrapper |
| URL rewriting                 | Only in ~lib/http.py~ (~proxy_prefix~, ~host_map~); SDKs return canonical URLs |
| Version                       | Lives in ~pyproject.toml~; ~pkit.version.get_version()~ reads the installed metadata |
| Version bumps                 | Via ~make bump VERSION=x.y.z~ / ~make release VERSION=x.y.z~; never by hand |

** SDK layer (library-only)

Success returns frozen dataclasses; failure raises typed exceptions. HTTP via
~pkit.lib.http.HttpClient~; external commands via ~pkit.lib.shell.run~; whole
downloads via ~pkit.lib.aria2c~ (~HttpClient.download~ with ~downloader=auto~
prefers it, falling back to the stdlib client when it is not installed);
rclone via ~pkit.lib.rclone~.
Clients are context managers and accept an injected ~http=~ so tests can
substitute a fake per instance.

** CLI layer (thin)

stdlib argparse; ~main(argv) -> int~ built on ~pkit.lib.cli.run_tool~.
Parse args → call SDK → print to stdout or fail to stderr → return the exit
code. ~--json~ affects success output only.

* 3. Contracts

** Exit codes

| Code | Meaning                                               |
|------+-------------------------------------------------------|
|    0 | Success                                               |
|    1 | Unknown / unexpected failure (retry not assumed safe) |
|    2 | Usage / input / auth / config error (user can fix)    |
|   75 | Temporary failure, retry later (BSD ~EX_TEMPFAIL~)    |

** stdout / stderr / stdin

- *stdout*: data only. Plain = one useful value or summary line. JSON =
  structured success object.
- *stderr*: short human-readable diagnostics (~Error: No target URL provided.~).
- *stdin*: when a command's primary argument is omitted or ~-~, read the
  first non-empty line (e.g. ~echo https://example.com | pkit wayback save~).
  An interactive TTY never blocks.

* 4. Style

Python 3.13+. Type hints on public interfaces. Frozen dataclasses for result
values. Short clear names, small functions. Comments explain *why*, not what.

Naming: clear and boring (~save_url~, ~job_id~, ~read_stdin_line~). Avoid
non-obvious abbreviations, cute names, generic names (~manager~, ~handler~).

* 5. Dependencies

stdlib first; pkit has zero runtime dependencies. A dependency is accepted
only if it removes significant code *and* is stable. Packaging stays in the
pip family: ~venv~ + ~pip~ + ~pip-tools~ + ~pipx~ (see
[[file:docs/workflow.org][docs/workflow.org]]).

* 6. Testing

pytest (parallel by default through ~pytest-xdist~: ~make test~ runs
~-n auto~, ~PYARGS="-n0"~ goes serial), fakes only at boundaries pkit does not
own: the network transport (~FakeHttpClient~ in ~tests/conftest.py~), the
aria2c and rclone binaries, remote backends. sqlite and the filesystem are
always real. CLI tests call ~main([...])~ directly via the ~run_cli~ fixture.

A few meaningful tests > many brittle tests. Tests serve as executable
documentation of the contract.
