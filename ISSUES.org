  - Options (decide): query DB via custom SQL; fetch all and filter in Python; or register a custom SQLite function.
  - Tags: :wayback: :workflow: :verify:

* DONE Evaluate moving Wikidata module into lib
  - Current wikidata module is complex and not pkit-meta specific.
  - lib/wikidata = general wrapper; pkit-meta/wikidata = adapter (possible future non-wikidata sources).
  - Concern: adapter API is complex and hard to design when only one source exists today.
  - Decision needed: keep concise, simple, elegant, and stable (project philosophy) — decide lib split for rclone + wikidata + aria2c together (same taxonomy).
  - Related to: rclone lib refactor, aria2c wrapper.
  - Tags: :wikidata: :lib: :refactor: :architecture:
  - Evaluation done; decision: stays in =pkit.meta=. The lib taxonomy is "general wrappers around
    external tools with no pkit domain knowledge" — aria2c and rclone qualify; wikidata does not:
    =extract.py= and =plans.py= map entities onto pkit.meta's record models, so a =lib/wikidata=

    philosophy forbids. Recorded as the boundary rule in README.org (Boundaries: "Wikidata stays
    in pkit.meta"). Revisit only when a second source exists.

* DONE Design project as multiple small projects (modular)

  - Ties into lib extraction decisions (aria2c, rclone, wikidata).
  - Tags: :architecture: :modular:
  - Decision: modular by enforced layering, not by multi-project packaging (four pyprojects and
